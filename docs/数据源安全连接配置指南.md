## 1. TLS/SSL 加密连接

### 1.1 什么是 TLS/SSL？

TLS（Transport Layer Security）/SSL（Secure Sockets Layer）是一种加密协议，用于保护网络通信的安全。

**使用 TLS/SSL 的好处：**

- ✅ **数据加密**：防止敏感数据（密码、查询结果）在网络中被窃听
- ✅ **身份验证**：验证服务器身份，防止中间人攻击
- ✅ **数据完整性**：确保数据在传输过程中不被篡改
- ✅ **合规要求**：满足金融、医疗等行业的安全合规要求

**适用场景：**

- 生产环境数据库连接
- 跨公网访问数据库
- 传输敏感数据（用户信息、财务数据等）
- 满足安全审计要求

### 1.2 证书和密钥说明

#### 1.2.1 三种证书/密钥

| 名称 | 用途 | 是否必填 | 说明 |
|------|------|----------|------|
| **CA 证书** | 验证服务器身份 | ✅ 必填 | 证书颁发机构（Certificate Authority）的证书，用于验证服务器证书的合法性 |
| **客户端证书** | 客户端身份认证 | ❌ 可选 | 用于双向认证（mTLS），服务器验证客户端身份 |
| **客户端密钥** | 客户端证书私钥 | ❌ 可选 | 与客户端证书配对使用，证明客户端拥有该证书 |

#### 1.2.2 单向认证 vs 双向认证

**单向认证（推荐）**
- 客户端验证服务器身份
- 只需 CA 证书
- 适用于大多数场景

**双向认证（mTLS）**
- 客户端和服务器互相验证身份
- 需要 CA 证书 + 客户端证书 + 客户端密钥
- 适用于高安全要求场景（金融、政务等）

### 1.3 如何获取证书

#### 1.3.1 从数据库管理员获取

**最常见的方式**是向数据库管理员或运维团队索取：

```
需要索取的文件：
├── ca.pem              # CA 证书（必须）
├── client-cert.pem     # 客户端证书（双向认证时需要）
└── client-key.pem      # 客户端密钥（双向认证时需要）
```

**注意事项：**
- CA 证书通常是 `.pem`、`.crt`、`.ca` 格式
- 客户端密钥必须保密，不能泄露
- 证书可能有有效期，注意及时更新

#### 1.3.2 使用云数据库的证书

主流云数据库都提供 SSL 证书下载：

| 云服务商 | 证书获取方式 |
|----------|--------------|
| **阿里云 RDS** | 控制台 → 数据安全性 → SSL 设置 → 下载 CA 证书 |
| **腾讯云 MySQL** | 控制台 → 实例管理 → SSL 管理 → 下载证书 |
| **AWS RDS** | 下载 AWS RDS CA 证书包 |
| **Azure Database** | 下载 Azure Database CA 证书 |

#### 1.3.3 自签名证书（开发/测试环境）

**⚠️ 警告**：自签名证书仅适用于开发测试环境，不应用于生产环境。

**生成自签名证书：**

```bash
# 1. 生成 CA 私钥和证书
openssl genrsa -out ca-key.pem 2048
openssl req -new -x509 -nodes -days 3650 \
  -key ca-key.pem -out ca.pem \
  -subj "/CN=MySQL-CA"

# 2. 生成服务器证书
openssl genrsa -out server-key.pem 2048
openssl req -new -key server-key.pem -out server-req.pem \
  -subj "/CN=mysql-server"
openssl x509 -req -in server-req.pem -days 3650 \
  -CA ca.pem -CAkey ca-key.pem -set_serial 01 \
  -out server-cert.pem

# 3. 生成客户端证书（双向认证时需要）
openssl genrsa -out client-key.pem 2048
openssl req -new -key client-key.pem -out client-req.pem \
  -subj "/CN=mysql-client"
openssl x509 -req -in client-req.pem -days 3650 \
  -CA ca.pem -CAkey ca-key.pem -set_serial 02 \
  -out client-cert.pem

# 4. 设置权限
chmod 600 ca-key.pem server-key.pem client-key.pem
chmod 644 ca.pem server-cert.pem client-cert.pem
```

**MySQL 服务器配置 SSL：**

```ini
# my.cnf 或 mysqld.cnf
[mysqld]
ssl-ca=/etc/mysql/ssl/ca.pem
ssl-cert=/etc/mysql/ssl/server-cert.pem
ssl-key=/etc/mysql/ssl/server-key.pem

# MySQL 5.7 支持的 TLS 版本
tls_version=TLSv1.2,TLSv1.3
```

**创建要求 SSL 的用户：**

```sql
-- 单向认证（只要求 SSL 连接）
CREATE USER 'ssl_user'@'%' IDENTIFIED BY 'password' REQUIRE SSL;

-- 双向认证（要求客户端证书）
CREATE USER 'ssl_user'@'%' IDENTIFIED BY 'password' REQUIRE X509;

GRANT ALL PRIVILEGES ON your_database.* TO 'ssl_user'@'%';
FLUSH PRIVILEGES;
```

### 1.4 配置步骤

#### 1.4.1 单向认证配置

**步骤 1：获取 CA 证书**

从数据库管理员处获取 CA 证书文件（如 `ca.pem`），保存到本地安全位置。

**步骤 2：在 DBridge 中配置**

1. 进入 **数据中心** → **数据源管理**
2. 点击 **新建数据源** 或编辑现有数据源
3. 填写基本信息：
   - 名称：`生产环境 MySQL`
   - 类型：`MySQL`
   - 主机：`your-mysql-server.com`
   - 端口：`3306`
   - 数据库：`your_database`
   - 用户名：`your_username`
   - 密码：`your_password`

4. 切换到 **TLS/SSL** 标签页
5. 填写证书配置：
   - **CA 证书**：粘贴 CA 证书内容，或填写证书文件路径
   - **客户端证书**：留空
   - **客户端密钥**：留空

6. 点击 **测试连接**，验证配置是否正确
7. 点击 **保存**

**证书内容格式：**

```
-----BEGIN CERTIFICATE-----
MIIDXTCCAkWgAwIBAgIJAJC1HiIAZAiUMA0GCSqGSIb3Qw0tEw...
...（证书内容）...
-----END CERTIFICATE-----
```

**证书文件路径格式：**

```
/home/user/certs/ca.pem
C:\Users\user\certs\ca.pem
/etc/mysql/ssl/ca.pem
```

#### 1.4.2 双向认证配置

**步骤 1：获取证书和密钥**

从数据库管理员处获取：
- CA 证书（`ca.pem`）
- 客户端证书（`client-cert.pem`）
- 客户端密钥（`client-key.pem`）

**步骤 2：在 DBridge 中配置**

1. 填写基本信息（同上）
2. 切换到 **TLS/SSL** 标签页
3. 填写证书配置：
   - **CA 证书**：`/path/to/ca.pem`
   - **客户端证书**：`/path/to/client-cert.pem`
   - **客户端密钥**：`/path/to/client-key.pem`
4. 测试连接并保存

### 1.5 验证 SSL 连接

**方法 1：查看连接状态**

在 MySQL 中执行：

```sql
SHOW STATUS LIKE 'Ssl_cipher';
```

如果返回非空值，说明 SSL 连接已启用。

**方法 2：查看进程信息**

```sql
SHOW PROCESSLIST;
```

SSL 连接会显示 `SSL` 标志。

**方法 3：使用 DBridge 测试**

在数据源列表中，点击数据源，查看连接详情，应该显示 SSL/TLS 加密状态。

## 2. SSH 隧道/代理

### 2.1 什么是 SSH 隧道？

SSH 隧道是一种通过 SSH 连接转发数据库流量的技术，适用于以下场景：

**使用场景：**

- ✅ **数据库未开放公网访问**：数据库只允许内网访问，需要通过跳板机连接
- ✅ **加密非加密连接**：数据库本身不支持 SSL，通过 SSH 隧道加密传输
- ✅ **绕过防火墙限制**：防火墙只允许 SSH 端口（22）通过
- ✅ **访问多个内网数据库**：通过一台跳板机访问多个内网数据库

**优势：**

- 🔒 **安全性**：利用 SSH 的强加密保护数据传输
- 🌐 **灵活性**：无需修改数据库配置或防火墙规则
- 🚀 **便捷性**：无需安装额外的 VPN 软件

### 2.2 SSH 认证方式

SSH 隧道支持两种认证方式：

#### 2.2.1 密码认证

**适用场景：**
- 快速测试
- 临时连接
- 不使用密钥管理的环境

**配置参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| SSH 主机 | 跳板机地址 | `jump.example.com` |
| SSH 端口 | SSH 服务端口（默认 22） | `22` |
| SSH 用户名 | 登录跳板机的用户名 | `ubuntu` |
| SSH 密码 | 登录密码 | `your_password` |
| 认证方式 | 选择 **密码** | - |

**优点：**
- ✅ 配置简单
- ✅ 无需管理密钥文件

**缺点：**
- ❌ 安全性较低（密码可能被暴力破解）
- ❌ 需要手动输入密码（不支持自动化）
- ❌ 密码可能在网络中传输

#### 2.2.2 密钥认证（推荐）

**适用场景：**
- 生产环境
- 自动化运维
- 高安全要求场景

**配置参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| SSH 主机 | 跳板机地址 | `jump.example.com` |
| SSH 端口 | SSH 服务端口（默认 22） | `22` |
| SSH 用户名 | 登录跳板机的用户名 | `ubuntu` |
| SSH 私钥 | SSH 私钥文件内容或路径 | `/home/user/.ssh/id_rsa` |
| 私钥密码 | 私钥的密码短语（如果有） | `your_passphrase` |
| 认证方式 | 选择 **密钥** | - |

**优点：**
- ✅ 安全性高（基于非对称加密）
- ✅ 支持自动化（无需手动输入密码）
- ✅ 防止暴力破解

**缺点：**
- ❌ 需要管理密钥文件
- ❌ 私钥泄露风险（需妥善保管）

### 2.3 如何获取 SSH 私钥

#### 2.3.1 生成新的 SSH 密钥对

**Linux/macOS：**

```bash
# 生成 RSA 密钥对（推荐）
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# 或使用 Ed25519（更安全）
ssh-keygen -t ed25519 -C "your_email@example.com"
```

**执行过程：**

```
Generating public/private rsa key pair.
Enter file in which to save the key (/home/user/.ssh/id_rsa): [回车使用默认路径]
Enter passphrase (empty for no passphrase): [输入密码短语，或直接回车留空]
Enter same passphrase again: [再次输入密码短语]
Your identification has been saved in /home/user/.ssh/id_rsa.
Your public key has been saved in /home/user/.ssh/id_rsa.pub.
```

**生成的文件：**

```
~/.ssh/
├── id_rsa          # 私钥（保密，不能泄露）
└── id_rsa.pub      # 公钥（可以分享给任何人）
```

**Windows（使用 Git Bash 或 PowerShell）：**

```bash
# Git Bash
ssh-keygen -t rsa -b 4096

# PowerShell（Windows 10+）
ssh-keygen -t ed25519
```

#### 2.3.2 将公钥添加到跳板机

**方法 1：使用 ssh-copy-id（推荐）**

```bash
ssh-copy-id -i ~/.ssh/id_rsa.pub user@jump.example.com
```

**方法 2：手动复制**

```bash
# 查看公钥内容
cat ~/.ssh/id_rsa.pub

# 登录跳板机
ssh user@jump.example.com

# 在跳板机上执行
mkdir -p ~/.ssh
echo "ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQ..." >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

#### 2.3.3 从云服务商获取密钥

**AWS EC2：**
1. EC2 控制台 → 密钥对 → 创建密钥对
2. 下载 `.pem` 文件（私钥）
3. 设置权限：`chmod 400 your-key.pem`

**阿里云 ECS：**
1. ECS 控制台 → 网络与安全 → 密钥对 → 创建密钥对
2. 自动下载私钥文件
3. 绑定到实例

**腾讯云 CVM：**
1. CVM 控制台 → 密钥对 → 新建密钥对
2. 下载私钥文件
3. 关联到实例

### 2.4 配置步骤

#### 2.4.1 密码认证配置

**场景**：数据库在内网，需要通过跳板机访问

**步骤 1：确认跳板机信息**

- 跳板机地址：`jump.example.com`
- SSH 端口：`22`
- 用户名：`ubuntu`
- 密码：`your_password`

**步骤 2：在 DBridge 中配置**

1. 进入 **数据中心** → **数据源管理**
2. 点击 **新建数据源** 或编辑现有数据源
3. 填写基本信息：
   - 名称：`内网 MySQL`
   - 类型：`MySQL`
   - 主机：**数据库的内网 IP**（如 `192.168.1.100`）
   - 端口：`3306`
   - 数据库：`your_database`
   - 用户名：`db_user`
   - 密码：`db_password`

4. 切换到 **隧道/代理** 标签页
5. 填写 SSH 配置：
   - SSH 主机：`jump.example.com`
   - SSH 端口：`22`
   - SSH 用户名：`ubuntu`
   - 认证方式：**密码**
   - SSH 密码：`your_password`
   - SSH 超时：`5`（秒）

6. 点击 **测试连接**
7. 点击 **保存**

#### 2.4.2 密钥认证配置

**步骤 1：准备 SSH 私钥**

确保你有 SSH 私钥文件（如 `~/.ssh/id_rsa`）。

**步骤 2：在 DBridge 中配置**

1. 填写基本信息（同上）
2. 切换到 **隧道/代理** 标签页
3. 填写 SSH 配置：
   - SSH 主机：`jump.example.com`
   - SSH 端口：`22`
   - SSH 用户名：`ubuntu`
   - 认证方式：**密钥**
   - SSH 私钥：粘贴私钥内容，或填写私钥文件路径
   - 私钥密码：如果私钥有密码短语，填写密码；否则留空
   - SSH 超时：`5`（秒）

4. 测试连接并保存

**私钥内容格式：**

```
-----BEGIN RSA PRIVATE KEY-----
MIIEpAIBAAKCAQEA2a2rwplBQLF...
...（私钥内容）...
-----END RSA PRIVATE KEY-----
```

**私钥文件路径格式：**

```
/home/user/.ssh/id_rsa
C:\Users\user\.ssh\id_rsa
```

### 2.5 SSH 隧道工作原理

```
┌─────────────┐
│  DBridge    │
│  (本地)     │
└──────┬──────┘
       │ 1. 建立 SSH 连接
       ▼
┌─────────────┐
│  跳板机     │
│  (SSH)      │
└──────┬──────┘
       │ 2. 转发数据库流量
       ▼
┌─────────────┐
│  数据库     │
│  (内网)     │
└─────────────┘
```

**工作流程：**

1. DBridge 与跳板机建立 SSH 连接
2. DBridge 在本地创建一个临时端口（如 `127.0.0.1:54321`）
3. 所有发往临时端口的流量都通过 SSH 隧道转发到数据库
4. SSH 隧道加密所有传输的数据

## 4. 常见问题排查

### 4.1 TLS/SSL 相关问题

#### 问题 1：测试连接成功，但展开表时报错 "tls: handshake failure"

**原因**：TLS 版本不兼容

**解决方案**：
- MySQL 5.7 默认支持 TLS 1.0-1.1
- 确保 DBridge 支持 MySQL 5.7 的 TLS 版本
- 联系技术支持更新 DBridge 版本

#### 问题 2：报错 "x509: cannot validate certificate for IP because it doesn't contain any IP SANs"

**原因**：服务器证书没有包含 IP SAN（Subject Alternative Name）

**解决方案**：
- 这是自签名证书的常见问题
- DBridge 已修复此问题，会自动跳过主机名验证
- 如果仍然报错，联系技术支持

#### 问题 3：报错 "failed to parse CA certificate"

**原因**：CA 证书格式不正确

**解决方案**：
- 确保证书是 PEM 格式（以 `-----BEGIN CERTIFICATE-----` 开头）
- 检查证书文件是否损坏
- 使用命令验证证书：`openssl x509 -in ca.pem -noout -text`

#### 问题 4：报错 "CA certificate must be self-signed"

**原因**：填写的 CA 证书不是真正的 CA 证书

**解决方案**：
- CA 证书必须是自签名的（issuer 和 subject 相同）
- 向数据库管理员索取正确的 CA 证书
- 使用命令检查：`openssl x509 -in ca.pem -noout -issuer -subject`

### 4.2 SSH 隧道相关问题

#### 问题 1：报错 "SSH tunnel failed: connection refused"

**原因**：无法连接到跳板机的 SSH 端口

**解决方案**：
- 检查跳板机地址和端口是否正确
- 确认跳板机的 SSH 服务正在运行
- 检查防火墙是否允许 SSH 连接
- 测试 SSH 连接：`ssh -p 22 user@jump.example.com`

#### 问题 2：报错 "SSH authentication failed"

**原因**：SSH 认证失败

**解决方案**：
- **密码认证**：检查用户名和密码是否正确
- **密钥认证**：
  - 确认私钥格式正确
  - 检查私钥是否有密码短语
  - 确认公钥已添加到跳板机的 `~/.ssh/authorized_keys`

#### 问题 3：报错 "SSH key permission denied"

**原因**：SSH 私钥文件权限过于宽松

**解决方案**：
```bash
chmod 600 ~/.ssh/id_rsa
```

#### 问题 4：连接超时

**原因**：SSH 隧道建立超时

**解决方案**：
- 增加 SSH 超时时间（建议 10-30 秒）
- 检查网络连接是否稳定
- 确认跳板机负载正常

### 4.3 性能优化建议

#### 建议 1：合理设置连接池参数

```yaml
连接超时: 10  # 秒
查询超时: 30  # 秒
最大连接数: 10  # 根据业务需求调整
```

#### 建议 2：启用连接复用

- SSH 隧道会自动复用连接
- 避免频繁建立和断开隧道

#### 建议 3：监控连接状态

- 定期检查 SSL 连接状态
- 监控 SSH 隧道的稳定性
- 及时更新过期的证书

## 附录

### A. 证书格式转换

**DER 转 PEM：**

```bash
openssl x509 -inform DER -in cert.der -outform PEM -out cert.pem
```

**PEM 转 DER：**

```bash
openssl x509 -inform PEM -in cert.pem -outform DER -out cert.der
```

**PKCS12 转 PEM：**

```bash
openssl pkcs12 -in cert.p12 -out cert.pem -nodes
```

### B. 常用 OpenSSL 命令

**查看证书信息：**

```bash
openssl x509 -in ca.pem -noout -text
```

**查看证书主题和颁发者：**

```bash
openssl x509 -in ca.pem -noout -subject -issuer
```

**验证证书链：**

```bash
openssl verify -CAfile ca.pem server-cert.pem
```

**查看私钥信息：**

```bash
openssl rsa -in client-key.pem -noout -text
```

**检查证书有效期：**

```bash
openssl x509 -in cert.pem -noout -dates
```

### C. 安全最佳实践

1. **证书管理**
   - 定期更新证书（建议每年）
   - 使用强加密算法（RSA 2048+ 或 Ed25519）
   - 妥善保管私钥，不要泄露

2. **SSH 密钥管理**
   - 使用密钥认证，避免密码认证
   - 为私钥设置密码短语
   - 定期轮换密钥

3. **访问控制**
   - 使用最小权限原则
   - 为不同应用创建不同的数据库用户
   - 限制数据库用户的访问范围

4. **监控和审计**
   - 启用数据库审计日志
   - 监控异常连接行为
   - 定期检查 SSL/TLS 连接状态
